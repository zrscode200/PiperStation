# Compact Handoff

Prepare or recover independent lane continuity for pause, native compact, or
handoff. Read STATION → Compaction for the canonical packet fields and resume
invariant; do not create a second field schema here.

## Prepare

1. Resolve project binding and select the intended lane through STATION → Lanes.
   A clear studio request selects its own design continuity even when execution
   lanes are open. Retain already selected work; ask only on real ambiguity.
2. Read its existing active work, ledger, packet and optional queue. For a studio
   read canonical design, relevant questions and relationships; for execution
   inspect assigned checkout/branch, actual git status and unresolved results.
   Read shared roadmap or decisions when relevant.
3. Reconcile related contracts, findings and their resolution owners. Preserve
   what remains valid and what requires revalidation. Inspect unresolved native
   workers and actual checkouts when available; record unavailable status as
   unknown. A wait timeout or old handle never establishes completion or death.
4. Read the old packet through `piper-record`, then prepare a full replacement
   outside hub records with only the non-derivable fields owned by STATION.
   Carry forward every still-relevant question, blocker and unrecorded finding.
   Do not append, section-edit, or regenerate solely from lossy compacted memory.
5. Publish with the observed digest. If stale, reread and reconcile before retry.
   Check ledger/windows/roadmap coherence, including partial source integration
   or interrupted multi-file publication. Commit useful paused continuity with
   the helper's path-only commit operation unless the user requests otherwise.
6. Report changed hub records separately from source and actual commit state.
   State that work is compact-ready; do not claim `/compact` ran. The user or
   native runtime invokes compaction. Finished small work with no open state
   needs no new packet.

## Resume

Read project binding and relevant memory/decisions, then the selected lane's
packet, active work, ledger, optional queue and canonical design. Derive live
repo path, branch/HEAD/status, changes since acceptance, and hub commit status
from their owners. Recover the exact next action and relevant source neighborhood.

Reconcile changed canonical revisions before dependent execution; studio resume
stays in the design phase. Verify native worker status and actual results before
restarting or reassigning work. If a handle cannot be observed, resolve ownership
without inventing liveness. If integration happened but records are incomplete,
inspect git and finish publication instead of repeating the merge.

Expand inspection for concrete triggers: stale packets, missing acceptance,
failing checks, shared contracts, permissions/security, generated parity, or
integrated review. Preserve original scope and authorization across resume.
